# Input types implementation and verification boundary

This stage expands text fields from text/password to the eleven types present in the Axure RP 11.0.0.4150 chooser: text, password, email, number, phone (`tel`), url, search, file, date, month and time. See the [official field documentation](https://docs.axure.com/axure-rp/reference/text-fields-text-areas/), [original-function experiments](input-types-evidence.md) and [native metadata/CIL evidence](rp-input-types-evidence.md). The retained extraction identity is `ev_ceacbf6838c7910ac5abb083528eae30fd831b34f6a9fdd3a4dd37c2891555b7`.

## Implemented behavior

- A shared strict model enum drives validation and the Inspector. Type changes preserve authored text, Hint, readonly, maximum length and submit bindings; undo, save/reopen, mixed selections, components and adaptive content retain those values. File Hint editing is disabled while the saved configuration remains available after changing back to a supported type.
- Preview and offline export use the same self-contained runtime. Native HTML value sanitization governs logical reads, conditions, Set Text and raw TextChanged comparisons. Invalid numeric/date/month/time values become empty; accepted numeric spelling is retained. Email/URL trim HTML ASCII whitespace without rejecting all syntactically invalid addresses. Textarea line endings become LF.
- Hint activity is independent of normalized display. A nonnumeric Hint may be active but invisible in a number field. Set Text uses the requested string's emptiness to update Hint, and native normalized text to determine whether TextChanged runs. Password Hint alone switches the underlying type to text.
- Files are selected locally through a real browser control and remain transient. Authored text cannot restore a selection. The logical value exposes the browser fakepath; Set Text with the same current path is a no-op, empty text clears, and a different nonempty value raises a visible error while retaining the existing selection. Export has no upload endpoint and blocks network/form submissions through its CSP.
- Runtime-private File objects survive hide/show and panel-state remounts through an in-memory selection cache. Clearing a hidden control also clears the cache; navigation, restart, row refresh and disposal release the corresponding selections. The cache is excluded from saved projects and serializable runtime snapshots. Browser tests verify the retained FileList and bytes, rather than only the displayed filename.
- Both players preserve one initial default value attribute and change the value property afterward. This prevents React from moving a number/time control's step base after every update. This is a consistent HTML behavior choice; the exact obfuscated vendor generator attribute output remains unverified. Equal-value renders leave an incomplete numeric edit such as `-` intact, including its native `badInput` state.
- Native readonly and maxlength attributes remain browser-driven. Readonly does not block File selection. Maximum length applies to text/password/email/phone/url/search keyboard entry; Set Text can exceed it. Focus/Select text works on typed inputs even when the browser exposes no selection range API.
- Native read-only recovery accepts the eleven proven chooser enum values with explicit mapping provenance. One actual Phone Number Input in the shipped Sample form patterns container now recovers. File recovery is deliberately restricted to empty native stored text and empty Hint with a validated form-properties protocol. No selected file is synthesized from project data.

## Verification and remaining limits

The release verification JSON records exact suite totals, frozen sources, source evidence hashes and the tested EXE/ASAR/ZIP. Tests cover module and serialized runtimes, actual browser authoring, preview and disconnected exported HTML, file selection/clear/error behavior, unchanged saved projects and the actual imported Phone field. Packaged tests mock OS file-dialog responses; they do not establish native picker appearance or complete library-format browsing support.

The original-function evidence uses isolated functions from the shipped player, with real Edge HTML controls. It is not an execution of the complete vendor prototype or a direct original-editor GUI comparison. Obfuscated generator type literals have not all been decoded; HTML type spelling follows the standard mapping, with native enum provenance recorded separately. Native min/max/step defaults, calendar/clock popup appearance, mobile keyboards, IME details and every possible date/number string remain unverified. The headless value fallback matches the measured Edge rules, including its date ceiling, rather than claiming all engines share the same range.

Full Axure parity remains incomplete. Advanced editor widgets, precise docking/layout, native writing, complete adaptive/interaction semantics, cloud collaboration and other gaps remain listed in [implementation status](../docs/implementation-status.md). Prior stage reports retain their historical test counts and hashes; use `release/verification.json` for the current downloadable package.

The final packaged Phone screenshot confirms editable telephone input, but also visibly shows clipped captions on the imported Personal information form. Its incomplete inherited text styles and geometry are not a visually faithful reconstruction of that native page. The independently authored eleven-type demo does not show this caption defect. This stage verifies recovery and input behavior; native-page appearance remains a separate open issue.
