## Documented scope and storage

[Official Inline Frame documentation](https://docs.axure.com/axure-rp/reference/inline-frames/) describes page, URL, and local-file destinations; automatic scrollbars and hiding borders; changing a frame through Open Link; and Parent Frame navigation. No/video/map/custom previews are author-canvas aids, not embedded playback content. Browser/site embedding restrictions and local-file restrictions still apply. The docs' general variable-sharing limitation should be distinguished from the optional URL snapshot mechanism demonstrated below.

[Independent format evidence](inline-frame-format-evidence.md) establishes native `ShowBorder`, scroll enum Auto/Scroll/Hidden, author preview enum, and the one real empty Default library frame. No nonempty native target is claimed recovered merely because the runtime supports authored targets.

The implemented schema is `inlineFrame:{target?,hideBorders,scrolling:'auto'|'yes'|'no',preview}`. `FrameTarget` is a typed page ID, literal HTTP(S) URL, or literal local path. `openLinkInFrame` selects widget or immediate-parent scope; widget scope has a separate widget ID. Preview images do not appear in the player.

## Independent reconstruction

Internal pages run in real sandboxed iframes with independent runtime instances. An internal page's ordinary navigation stays in that frame. Parent-frame requests go to its immediate enclosing runtime. Variables and transient widget state are separate between sibling frames; navigation within one child runtime follows the product's existing page-navigation contract. The optional native `includeVariables` URL snapshot setting is **not in this milestone's model**.

Both renderers use the same `createInlineFrameHost` and portable runtime. Widget-scope frame actions update a transient destination and revision; repeating an identical target starts a fresh document. These records participate in segment rollback, row refresh, and page reset. Hidden frames and frames in inactive panel states stay mounted, preserving their browsing context through unrelated rendering. Row refresh intentionally recreates the row's frame. A non-frame sibling update does not reload a frame.

Offline export lazily creates each internal child as a `srcdoc` document carrying the validated project and independent factories. It does not eagerly expand nested HTML. Font bytes occur once in the root stylesheet; each child receives that stylesheet's `textContent` at runtime. The editor retains `script-src 'self'`: experiments showed that both srcdoc and data URLs inherit that restriction. Editor preview therefore first navigates to a fixed `frame-player.html` with its own script policy. Vite's directly declared build API uses `scripts/frame-player-build.ts` and the `public/frame-player.html` template to create one self-contained HTML document; the only executable script is authorized by its exact SHA-256 CSP hash. Dev middleware and production emission call this same builder. No new dependency or editor script-policy relaxation is required.

Actual packaged Electron diagnosis demonstrated why an external classic script is insufficient: the opaque `file://` child loaded `frame-player.html`, but Chromium rejected its local `frame-player.js` request before any script or handshake ran. After embedding the CSP-hashed script, the first level worked; a further real probe showed that an opaque child also cannot fetch another local player HTML. Nested internal pages therefore reuse the same fixed template through `srcdoc`, with the identical authorized script and a per-instance token meta element. The player captures its pristine template before mounting, removes the previous token, and performs the same one-shot handshake at every depth. This preserves the opaque sandbox and works in both HTTP development preview and file-based desktop preview.

All frames have `sandbox="allow-scripts allow-forms"`, without same-origin, top-navigation, popup, or desktop privileges. The first fixed player receives a 128-bit random token in its fragment; a changing query parameter forces a document reload. Nested fixed-template players receive a fresh token in a non-executable meta element. Only the corresponding WindowProxy and token can complete the one-shot initialization handshake. Project data is not sent to an old external document merely because it retains that WindowProxy. Child navigation messages use the same identity checks. Removed records and page changes revoke those permissions. Main-frame-only Electron IPC/preload checks are separately implemented and verified by the parent task.

External HTTP(S) URLs remain literal and are validated again at the sink. Local paths require a file-based playback base and the shared strict `frameFileUrl` resolver. An HTTP-hosted preview displays a clear error for local files. The packaged desktop uses a file base, and its actual local/loopback navigation is part of the parent task's smoke validation. External embedding may be blocked by a remote server; the product cannot override that policy.

Plain text/style JSON is escaped before insertion into offline scripts, and no executable `innerHTML`, eval, or Function construction was added. Fixed-player messages insert CSS with `textContent`. The existing export-injection test remains unchanged and passes.

## Deliberate bounds and unverified native details

- Internal recursion is stopped for an ancestor-page cycle or six nesting levels. A conservative distributed 32-frame **internal-page loading budget** limits expansion; external/blank iframe DOM nodes are not claimed covered by that internal budget. These are product limits, not native Axure limits.
- Parent-frame navigation errors are caught and presented to the host; Page Loaded failures do not become unhandled promise rejections.
- URL snapshot variables, native expression-valued frame URLs, popup options, special browser media behavior, remote-site restrictions, and exact browser-default border pixels are not claimed fully reproduced.
- Scroll modes map to native iframe scrolling attributes; browser support and cross-origin content determine actual scrollbar behavior.
- Frame focus/click events inside an opaque child document do not bubble into the parent widget. No synthetic forwarding of arbitrary remote DOM events was added.
- Original navigation is permissive; the reconstruction deliberately rejects script URLs and credentials and uses an opaque sandbox. It does not reproduce unrestricted parent access.
- Source bounds and authored opacity are preserved. This is not a claim that every native frame CSS property has been pixel-compared.

## Packaged hidden-window input synchronization follow-up

The rebuilt package `app.asar` SHA-256 `bf7010f8f724e7ea26ff776a91093cf45c372dc5c16b881593f8fea47e706640` loaded and navigated real internal pages, but its hidden desktop smoke sometimes left Count at 1 after Playwright reported a successful physical click. [The independent diagnostic](scripts/diagnose-inline-frame-reload.mjs) added capture-phase event logging before document creation; it did not modify product code, the package, or the parent smoke/audit.

- [No additional synchronization](inline-frame-runtime-reload-none.json): the failure reproduced even on the initial document. Count changed 0 → 1 normally, and no subsequent document navigation occurred. The trusted pointer/mouse/click sequence landed on the **root editor's iframe element**, with no matching child-document pointer/click event. This rules out a delivered button action being undone by an old runtime in that observation.
- [Two child requestAnimationFrame callbacks](inline-frame-runtime-reload-raf.json): the same input-routing failure persisted. DOM readiness and two animation frames alone did not establish the hidden frame's composited hit-test readiness.
- [Hidden capture completion](inline-frame-runtime-reload-capture.json): after Count 1 was visible, awaiting the containing BrowserWindow's `webContents.capturePage(undefined, {stayHidden:true})` produced a nonempty PNG, then the unchanged ordinary `locator.click()` passed on the initial document and three successive Detail → Reload documents. Each of the four distinct child document instances received a trusted click on the actual increment widget, immediately followed by Count 2. No root-iframe clicks occurred. All windows stayed hidden; console errors, failed requests, and page errors were empty.

This is an observed hidden Electron compositor/input synchronization limitation, not a native Axure behavior or a reason to change runtime counter semantics. The narrow harness synchronization is capture completion after a new frame document becomes ready, followed by the original physical click and strict result assertion. It does not use forced clicks, DOM click calls, blind sleeps, or result-swallowing retries. The parent task owns the final package smoke with that synchronization; these four-document observations do not substitute for the full package verification.

A second diagnostic isolated root-button clicks in a separate hidden Electron BrowserWindow loading the **actual newly exported offline HTML**. The requested 1550×1050 window had an observed CSS viewport of 1266×617 at DPR 1.5. After the child counter reached 2, the root Update button's rectangle was `(790,686,226,42)`, below that viewport. Capturing **before** `locator.click()` did not suffice: Playwright's automatic scroll then moved the button to y=338, while the hidden compositor's previous hit-test data routed the trusted click to the right child's description (local 113,81). The root handler never received it. A later physical click, with the layout already composited, worked. [Baseline events/layout](inline-frame-runtime-offline-root-baseline.json) and the screenshot before automatic scrolling preserve this distinction.

The required observable synchronization order is therefore **`locator.scrollIntoViewIfNeeded()` → containing BrowserWindow `capturePage(...,{stayHidden:true})` completion → ordinary `locator.click()`**. Two independent fresh Electron processes using this order both delivered the first root click to `frame-sibling-update` at root coordinates `(903,359)`, produced `Outer text updated`, and preserved child Count 2; no retry was taken. [Run one](inline-frame-runtime-offline-root-scroll-one.json), [run two](inline-frame-runtime-offline-root-scroll-two.json), and the [independent diagnostic source](scripts/diagnose-inline-frame-offline-root.mjs) retain the input targets, capture timestamps, bounds, hidden-window checks, and empty error collections. The post-scroll screenshot was visually inspected. Product source, built HTML, app.asar, and the parent's smoke script/audit were unchanged by this investigation.
