# UX heading font size: native format evidence

This is a focused, read-only investigation of four stored RP11 text owners. It does not change the importer, font divisor, authored document, or the frozen rotation release. **The traced conversion is native size × 96/72; the evidence does not justify changing it to make a saved rectangle fit.** The complete original project-loading and HTML-generation lifecycle has not been executed, so this report does not claim that opening the original UX project and exporting it must produce the current imported 28px result.

## Observed stored conflict

All four are VectorShape / Shape0. Both `AutoFitWidth` and `AutoFitHeight` are explicitly true. Local MyStyle has no FONT_SIZE/P2 entry. Its exact cached MatchInfo resolves `T Heading`, style ID `022072535e854a3b9c6057e2559f639a`, library ID all zero, with determined-and-overridden P1=`Open Sans`, P2=**15**, P1001=700. The default cached P2 is 9.75. The relevant local Size/P105 and Location/P101 retain the rectangles above.

Each owner instead stores one paragraph and one `Axure:AttributedString:AxRun` with Family=`Open Sans`, **Size=21**, Weight=700, Style=0, Stretch=5, Underline=false, Strikethrough=false, Baseline=0, CharacterSpacing=0 and Color=-16777216. Paragraph LineSpacing=0, Wrapping=0, Trimming=0 and HorizontalAlignment=0; list settings are zero. There is no hyperlink or second run in these four owners.

The current reader preserves that explicit run and computes 21/.75=28px. Its uniform-run base font recovery also reports 28px, with `uniform-rich-text-runs` provenance; the named style by itself would convert 15/.75=20px. Padding is already `[0,0,0,0]`, vertical alignment top, line height normal. This is distinct from the previously fixed default-5px caption padding issue.

## Narrow post-load synchronization check

`RichTextObject.WNZO` (100702351) calls `RichTextPanel.RNO1` (100701880) with false at IL130/131. RNO1 sets AttrString, runs its initialization/normalization hook, then IL109/110 branches to return450 for false. It therefore skips its optional `SyncStyleToAttrString` call at IL261 on **this particular loading path**. The one nonempty-run case does not require adjacent-run merging.

The new [font-size-format-sync-callers.json](font-size-format-sync-callers.json) is a bounded token call-byte search, followed by full disassembly verification of both hits: RNO1 above and `InlineLink.MIue` (100700952) at IL78. The latter is a property-change hook on an InlineLink, which these owners do not contain. [font-size-format-sync-cil.json](font-size-format-sync-cil.json) and [font-size-format-link-sync-cil.json](font-size-format-link-sync-cil.json) preserve the methods.

This has **not** found a verified whole-document load hook that changes these owners' run21 to named-style15. It also does not prove that every indirect callback, alternative synchronization method, or later layout path has been exhausted. No unrestricted scan or target-code execution was used to bridge that gap.

## AutoFit and measured-fit boundary

The sibling's separate static generator investigation establishes that `FNiU.rNPL` (100699663) calls the VectorShape text-layout hook PNZ8 before reading TextPanel.Rect. PNZ8 calls `RichTextPanel.INOR` (100701896); AutoFitWidth=true selects `GtCX` (100715355), which requests measuring width10000 from KIf5 and writes the returned TextPanel.Rect. See [font-size-runtime-autofit-replay.json](font-size-runtime-autofit-replay.json). Its graphics-size sink is mocked; it is **not** an original font-metric measurement. This establishes that initial text layout is not just a transcription of the saved owner rectangle. It does not by itself prove owner outer-bounds expansion or final original exported pixels.

Parent's independent actual packaged-Electron experiment is preserved in [font-size-browser-probe.json](font-size-browser-probe.json), with input document [font-size-imported-before.rea.json](font-size-imported-before.rea.json). It checks CDP platform fonts and isolates DOM-only candidate sizes without changing the saved project. Using the shipped Open Sans Bold font, 20px has unwrapped text widths approximately94.1797/53.1152 for Problems/Ideas and fits95/54×27; 21px has98.89/55.77 and28px has131.85/74.36, which wrap in those saved widths. The JSON and its immutable screenshots distinguish baseline28, native-font28/21/20, and restored28.

**Inference only:** those stored rectangles are a particularly close match for the cached base size15→20px. That does not establish whether they are stale AutoFit snapshots, whether native loading later reconciles named styles and run styles, or which dimensions the original generator finally emits. Original Axure GUI opening/generation of the sample remains unverified. No keyboard/dialog attempt is treated as a successful original sample opening.

## Effect on other known samples and implementation decision

[font-size-format-impact.json](font-size-format-impact.json) reads the frozen pre-rotation import snapshot only; it does not recensus or alter eleven original samples. It counts1766 base fontSize fields,647 structured-rich owners and2162 run fontSize fields. These are model-field counts, not visible glyphs or a claim that every base field originated in native P2; model defaults also exist. Icons was rejected by the existing page limit and contributes zero.

Known source-backed examples retain required conversions: Required Fields Email10.5→14px, Error Message13.5→18px; three Basics mixed-font owners have local P2=13.5→18px and explicit run Size16.5→22px. A global divisor removal would incorrectly shrink the explicitly converted values. Globally preferring base P2 over run Size would erase genuine run formatting, including those Basics examples.

**No parser/model/rendering change is justified by this investigation alone.** Preserve current source characters, explicit run styles, native unit conversion and stored bounds. The next decisive evidence would be a verified original project load/style-sync trace or original generated output establishing the effective text style and AutoFit owner/text-panel rectangles for these exact four identities. This report deliberately leaves that result unknown.
