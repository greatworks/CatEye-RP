## Implementation boundary and remaining limits

The source-supported ordinary composition is: keep captured body/path geometry separate from declaration-derived CSS crop, omit viewBox and root dimension attributes after the native inline rewrite, and do not add a compensating padding transform. Parent browser evidence separately establishes the hidden overflow default; this report does not derive browser clipping from matrix algebra.

The root renderer candidate at SHA-256 `8c19c834df2ff2123e4c36eb527b8b9b0f1847ccdf63e9ff66e06baf850c84a1` follows that matrix contract. Read-only review identified a declaration validation hole when a valid retained paint snapshot masked non-finite declaration b/w used for crop. The parent repaired it by validating source b/w, nonnegative values and the finite sum before DOM changes; it does not impose source strokeWidth < captured assetSize. The parent's already-written validation report was read and records 496/496, not rerun by this investigator.

One independent path serialization difference was raised to the parent: the original radio dot begins at bottom-mid, uses four cubic curves returning to the starting point and has no Z. The candidate generic ellipse began at top-mid and used Z. Fill geometry can be equivalent while closure/start-point differences remain relevant once runtime stroke is added. The parent chose to fix this separately; that correction needs its own final read-only review. The matrix/crop conclusion does not depend on that pending path adjustment.

Arbitrary rotations, shadows, nonordinary opacity/clip groups, nonidentity graphics ancestors, general exception disposal, gradient brushes, full native root serialization, browser antialiasing and complete original GUI/pixel equivalence remain outside this bounded claim. The overall reconstruction is not complete.
