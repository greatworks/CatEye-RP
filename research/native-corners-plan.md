# 原生圆角语义：本阶段工作与完整目标

完整目标仍为分析并重建 Axure RP 11 的编辑、运行、文件和协作工作流。上一轮已修改代码并验证发布包，属于进展；本阶段不是对完整一致性的重新定义。当前 `.rp` 双向互通、云协作、原版 GUI/像素等缺口仍保留在 `docs/implementation-status.md`。

当前已发布 All Views 阶段的 SHA、源码、构建输入、测试证据、ZIP 逐文件内容已重新核对；备份和核验记录在 `.build/native-corners-preflight.json`。本阶段在新候选通过前保留旧发布目录。

## 要解决的已知差异

已有静态证据显示 P71 CornerRadius 为统一值，P81 CornerVisibility 为独立 Position 掩码。产品的任意四值 `cornerRadii` 及组合重置并不能证明原生等价；导入目前根据存储控制路径推导四角，不能据此随意恢复自适应 P71/P81。本阶段须先核实顺序、默认值、几何与属性来源，再实现。

## 验收要求与证据

1. 以原始 DLL/资源字节建立半径、角掩码、夹取及边框联动的合同，区分静态/受控重放/原版实际观察。
2. 独立字段贯通严格保存校验、组合/复制、当前和所有视图、状态效果和样式动作；对实际同值和异值多选保持正确属性来源。
3. 作者界面有原生圆角编辑入口；旧独立半径工程可读取，不以静默丢失旧数据实现迁移。
4. 画布、预览、嵌套框架与离线导出采用同样的几何规则；用独立预期验证真实操作与实际渲染。
5. 原生格式恢复仅接入被证据支持的范围，真实样本结果和合成载体分开报告，严格拒绝未知有效值。
6. 保留真正的失败记录，修复后运行相关与完整必要测试；独立复查后测试候选 EXE，逐文件验证 ZIP，保存旧证据。
7. 原版 GUI/逐像素仍需实际原版画面才可声称完成。本轮 Computer Use 截图失败不能被产品截图或静态重放替代。

## 分工与顺序

- feature evidence：原版作者/绘制/生成器语义与受控重放，仅新增证据。
- format research：原生载体与真实样本，先研究，合同确认后再限定导入实现。
- editor core：先审查模型/作者命令；合同确认后独占模型和作者源文件及相关单元测试。
- 主线程：原版可观察界面、最终合同、渲染/播放器、浏览器与实际包验证、整合审查和发行。写入根 artifacts 的浏览器与桌面套件串行运行。

不改原版样本、不运行原版 DLL 的内部函数、不额外安装分析引擎。本阶段所有 native-corners 报告新增保存，不覆盖前阶段的冻结结论。
