# Adaptive placement: authoring evidence and integration contract

This is a static authoring investigation of the retained RP 11 assembly and the current reconstruction. It does not run the original program, retry its unavailable canvas capture, or establish original GUI pixels. The accompanying JSON binds the assembly, new CIL records and inspected product files by SHA-256. Source CIL offsets below are hexadecimal; tokens are decimal and build-local.

## Confirmed author workflow

[Official Adaptive Views documentation](https://docs.axure.com/axure-rp/reference/adaptive-views/) (read 2026-10-15, sections “Editing diagrams” and “Unplaced widgets”) states that child-view Delete unplaces an object, while Base or Affect All Views Delete removes it globally. Context commands separately restore placement or delete globally. The Outline retains unplaced objects, marks them red and offers a placed/unplaced filter. Inserting in a child view makes the new object unavailable in ancestor views unless Affect All Views is active. Ordinary property inheritance still respects a child's local override. This is official workflow evidence, not a captured native interaction.

## Pinned managed command paths

Assembly `AxureRP11.dll`: `dae5748f6be3e69c063ef117bab0b400586d94adf119f5a9ba260df59dc4e4a7`. The reader is `research/scripts/inspect-rp-serialization.ps1`, which uses ECMA metadata and reads CIL bytes without loading the target assembly. Opaque arithmetic and control-flow fields are retained rather than silently decompiled into invented source. The decoder's leading unreachable junk calls are not evidence of actual command invocation.

* `Axure.Constants.BoolOverride`: IGNORE=0, TRUE=1, FALSE=2. `KJm7.nJmQ` (100695337), IL22–2C writes property 111 with that carrier through `oJ0u`. This is different from visibility property 110. Format/runtime workers independently bind the downstream property to limbo; this report does not replace their reports.
* Outline `CByV.Unlimbo` (100671796) obtains the selected outline items, projects their source owners and calls `EFqs.QFUg` (100682427). `QFUg` forwards to `XcY.wDI` (100665343). `wDI` constructs a `uSWL` edit transaction, calls `AD3` (100665344), then submits it through `zImy`.
* `AD3`, IL4B–9C, obtains `PlacedStyleToInherit`, uses that style if present or constructs an `ituB` with `atla(TRUE)`, calls the owner's `GetEdit`, records that owner in the transaction, and applies the returned edit with `kIs0`. Its Layer branch (IL2D–46) recursively processes Layer diagram objects when a style-to-inherit exists. Thus restoration is not safely described as “always recurse a Boolean into every child.”
* `EFqs.Limbo` (100682639) checks the Limbo capability, current selection and eligibility; its successful command path selects the filtered objects and calls `XcY.ND1` (100665342). `ND1`, IL50–5E, constructs `ituB`, sets `atla(FALSE)`, and calls `bDR` (100665346). It is a style edit, not removal from the document object collection.
* `bDR` records edited owners in `uSWL`, asks each owner for `GetEdit`, applies it, handles table update bookkeeping separately, then submits the transaction. `uSWL` exposes `Commit`, `Combine` and its inherited edit-record path. This establishes native undo participation, not a measured number of GUI undo keystrokes.
* `KJm7.GetEdit` (100695569) with its Boolean argument false compares the requested style to the current effective provider. `kIs0` (100695566) forwards into `sJp1` (100695567, compiler lambda anchor `SetStyleInternal`). Contained owners delegate to their containing owner at IL13–2B.
* `sJp1`, IL92–12A, branches on `EditAllAdaptive`: the all-views path enumerates the overridden property keys, calls `WJpV`, then writes the Base provider; the ordinary adaptive path writes the current provider. `WJpV` (100695539), IL36–60, visits local adaptive style values and removes the supplied properties. Consequently Affect All Views is not equivalent to writing only the active view or merely its descendant views. Other local properties must survive this property-specific clearing.
* `KJm7.OIuf` (100695335), the `Placed` property getter, combines effective placement with a separate `UnplacedOverride`. The presence of that separate internal override is a warning against conflating source placement, temporary authoring reveal and `Visible`.
* `SJ0z` (100695536; lambda `ClearPlacedFromAdaptive`) is a separate, more complicated operation: it delegates containment, iterates adaptive maps, checks view relationships and an optional ID set, removes P111 or writes FALSE, then updates Base. This investigation does **not** substitute a guessed interpretation of all its insertion/master branches for a completed call-chain proof.

The native source has explicit placed-object queries on DynamicPanel, Layer, ReferenceDiagramObject and Repeater (tokens in the metadata JSON). Their existence is not proof that all those types use the same authoring recursion or that the reconstruction's components equal native RDOs. Locks/capabilities, exact selection restoration after undo, clipboard placement migration, independent masters and mixed selections crossing those boundaries are not fully executed here.

## Current reconstruction: concrete integration surfaces

* `src/model/types.ts` and strict `document.ts` validation currently have no placement field. `hidden` is already a different required property. Add optional Boolean `Widget.placed` and `AdaptiveWidgetOverride.placed`, defaulting semantically to true without filling old files.
* `src/model/adaptive.ts`: `ADAPTIVE_LAYOUT_FIELDS`, `combinedOverride`, `resolveAdaptiveWidgets`, `layoutDifference`, `preserveUnchangedDeclarations` and `applyAdaptiveWidgetEdits` currently govern visibility/layout. Placement needs an explicit sparse declaration path: an explicit true reset must not disappear because it equals the current inherited value. Resolution must retain the complete graph, not filter unplaced nodes before editing.
* The same file treats additions and deletions as shared content. New child-view additions need Base false plus current true when All Views is off; this rule must cover paste/library/image/pen/component insertion consistently. Passing a filtered canvas list into `applyAdaptiveWidgetEdits` would otherwise delete missing objects globally.
* `adaptive-view-sets.ts` resolves active definitions and preserves inactive `adaptiveOverrides`. All-views placement clearing must visit active and inactive maps; commit/prune must retain surviving IDs and all other declarations. Set switching must not turn an unplaced object into a missing target.
* `App.tsx`: `changeWidgets` commits the full current editing scope back into the page; `removeSelected` always deletes today. Keyboard Delete, Cut, menu Delete and an explicit Delete from All Views require separate dispatch. Canvas mapping, selection frames, marquee, select-all, keyboard movement and pointer start must exclude unplaced render candidates while Outline keeps the stored owners accessible.
* Outline is inline in `App.tsx`, not a separate component. It currently has only hidden/lock buttons and its source is the full editing-scope `widgets` array. A red status and separate Place/Unplace control can preserve that recovery path without abusing the eye button. Nested panel/repeater editing must not let an unplaced parent silently become an editable visible scope.
* `WidgetView.tsx` recursively renders panel children and repeater templates in the static editor. These static branches need placement filtering independently from ordinary hidden styling; root filtering alone leaks unplaced nested objects. Table/menu/tree structural editing must retain its existing shared-content and no-hole constraints.
* `document.ts` traversal, clone/remap and `components.ts` preserve generic widget properties through spreads/structuredClone, but validation and per-page declaration pruning require explicit tests. Placement is not an identifier and does not require action-reference rewriting. Unplace must leave action targets, links, states, child IDs and component source IDs intact. True deletion continues existing target/reference policy.

## Proposed implementation contract and tests

Use optional `placed?: boolean`, omission meaning true. Effective placement follows Base and the ancestor chain. Parent placement suppresses its rendered subtree without overwriting each child's stored placement. Keep placement independent of hidden and locked.

Provide an explicit pure placement command on the complete effective page. Current-view commands write a local true/false; All Views writes Base and removes only placement keys in every saved adaptive map. Preserve unrelated properties and explicit local overrides in descendants for ordinary current-view edits. Return the same page for a semantic/document no-op. A separate delete command decides child unplace versus actual graph removal; explicit global deletion always removes the graph.

The all-views switch should be clearly scoped if the product does not yet implement it for all visual edits. Do not label a placement-only switch as a faithful general Affect All Views control. Native special Layer restore, master/RDO sets and clipboard view-map migration need explicit limitations or further evidence; they must not be hidden behind generic recursion.

Focused acceptance should prove:

1. Old JSON round-trip adds no placement keys; true/false and malformed values are strictly validated, active and inactive maps round-trip.
2. Base→parent→child and sibling inheritance; explicit true overrides false; explicit unchanged resets survive later ancestor changes. Hidden and placed combinations stay independent.
3. Child Delete retains every ID/content/reference/map except placement; Base/All Views/global Delete removes the intended subtree and prunes declarations. Locked/noneditable structural descendants follow existing guards.
4. Place/Unplace is one undo transaction, no-op produces none; Outline restores an unplaced object without exposing it to canvas drag/marquee. Hidden objects keep existing editor semantics.
5. All Views clears only placement overrides across active and inactive maps and preserves unrelated style/geometry/state data. New child insertion appears in its branch, not Base/ancestors/siblings; all-views insertion appears everywhere.
6. Nested panel state/repeater template, whole table/menu/tree, clone/component ID stability and source-graph preservation. Do not introduce independent cell/node placement unless its native/model contract permits it.
7. Shared set reassignment, saving/reopening and runtime/portable visibility are tested separately. Runtime must implement limbo semantics, not simply call Hide. The runtime worker owns action targeting, lifecycle, focus, fit and row-instance behavior.

No product source, test, old evidence, browser or package was changed during this investigation. Product implementation and its red/green evidence follow as separate artifacts.
