# Native corners: final independent integration review

No new blocking defect was found in this bounded review. The prior large-single-corner family defect (NC-REVIEW-01) remains corrected. The final source, compared with `.build/before-native-corners/src`, passed **43 independent checks** in `native-corners-final-review.json`. This is product module/serialized-factory execution, an actual `App.patchSelected` source slice with explicit host sinks, and joins of retained native import/census evidence. It is not a browser, package, or original Axure GUI run.

The original eight renderer checks were rerun into this new report without overwriting `native-corners-render-review.json` or its observed-failure record. The final report binds every inspected source/test file, the available before-stage source snapshots, the exact App slice, the probe, and original evidence by SHA-256. Product hashes were checked again after execution and were unchanged.

## Author and model integration

P71 (`radius`) and P81 (`cornerVisibility`) remain independent in validation, merging, adaptive differences and All Views cleanup. The new four-boolean mask is atomic; changing one checkbox constructs a complete mask from each target's own effective mask. A radius command still removes the older independent-radius extension, but does not clear the native mask. No schema conversion treats the legacy four-radius tuple as original P81.

Static inspection followed `CornerEditor` / `CornerOverrides` through Inspector's corner intent and `App.patchSelected`. The executing slice confirmed heterogeneous selected targets retain their other three corners and their own radius. Current-view edits leave inactive declarations intact. All Views clears the changed property in inactive maps, preserves the other native property, and preserves an equal-value target's declarations. State edits use each target's own patch rather than copying the focused target's patch. Unsupported arbitrary paths in the same selection remain untouched. Action controls use the same patch helper against their explicit action target; removal of radius and removal of mask remain separate operations.

The tree-label, menu-item and table-cell routes were inspected in App; they call the same target-local edit callback through their existing structural patch functions. The new executable App cases exercise the ordinary selection route, not a mounted React tree or every composite route. Current/All Views behavior for native P71/P81 is supported by the frozen prior native authoring chain; the retained legacy independent-corner UI and product capability policy remain implementation choices.

## Renderer integration

The final `supportsSides` change recognizes a declared, normalized rectangle family even after a nonuniform aspect resize. The test uses an original 200×100 TL90 path at 80×240; sides/corners remain editable, and a deformed cubic handle disables regeneration. Module and serialized factories both pass. Existing legacy vectors without a declared native mask keep their prior saved-path policy.

The eight prior checks still cover the corrected large corner, all 256 corner/border equality combinations and an all-false corner mask retaining its square gradient border. React and offline use the same geometry/CSS helpers. Fill and stroke remain separate paints and definitions, and shadow paths continue to consume the resolved shape geometry.

Two source distinctions remain limitations, not defects hidden by this result: original dynamic SVG updates skip reconstruction at zero border width or line-pattern `none`, while the product declaratively regenerates edited native parameter geometry; and initial managed oversized fill clamping can differ from later JavaScript SVG clamping. This review does not establish original initial-render pixel equivalence.

## Strict native projection and six newly recovered cases

Reader/importer inspection confirms the native mask does not authorize arbitrary vectors. Base native corners require the supported surface, complete radius/mask provenance and a verified rectangle snapshot; partial state patches require a complete admitted base surface. P71-only and P81-only state/adaptive patches remain independent. Unknown shapes, malformed masks and conflicting legacy tuples remain strict rejections. The native importer's older saved-rectangle recognizer still has its historical restricted radius limit; the newly widened renderer family does not silently widen native import acceptance. There is no real oversized-positive import claim in this stage.

The final audit records 1,256 projected corner widgets, 52 partial masks, no new widgets and six new events/actions. Independent joins verified all six source owner IDs, source-file hashes, Click conditions, self-target mapping, selected patches and hover patches. A second join against the raw census verifies all 18 active OD corner properties across these owners: six MouseOver P71 values, six Selected P71 values and six Selected P81 values.

The exact action is **`setSelected` with value `"true"`**, not a toggle. Two owners initially selected preserve the former snapshot's **non-corner** paint via Base plus Selected style; their corner geometry is intentionally corrected from the prior saved-path snapshot to the recovered Selected P71/P81. The audit explicitly records this difference. No claim of full old/new appearance identity should include those corrected corners.

Only the new final-review probe, JSON and this Markdown report were written. No production source, existing test, frozen original evidence, import audit, browser output or package artifact was changed.
