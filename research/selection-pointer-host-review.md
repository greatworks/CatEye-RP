# Selection pointer resize: host design review

Read-only review of the pre-integration host. Source hashes and exact anchors are in `selection-pointer-host-review.json`. No source/test changes, browser execution, original DLL invocation, or original GUI retry were performed. This is a product-host design contract; the native pointer controller's numerical and panel-lifetime contract is being investigated separately.

## Observed current behavior and concrete integration hazards

1. `App.startDrag` increments the selection-command serial before eligibility, selection, or lock checks. A font-delayed property intent is therefore cancelled even by an attempted drag that is later rejected. The agreed next-stage policy is to reject pointer start while the property FIFO is pending, with a notice, before changing serial, context, selection, or document. Existing standalone Size latest-command cancellation remains a separate documented path.
2. Selection controls currently follow generic `resizeRotatedBounds → changeWidgets`, which applies an 8px minimum and rounded dimensions without the selection Size/fit/layout transaction. This does not implement the native selection layout contract. The new selection path must not inherit that minimum, rotation support, or fit behavior merely because the generic function is convenient.
3. Generic pointer frames already use the original effective widget list and original document, which avoids accumulating resize deltas. However, `planWidgetChanges` reads the current page/view/scope/Affect-all-views closure. The original widget/doc snapshot alone does not bind an asynchronous result to its starting context.
4. Inspector `planSelectionDocument` cannot be inserted unchanged into pointer frames: its validity predicate requires no drag, and it is designed for one command/commit. Current `pointerUp` clears the drag and finalizes history synchronously. If fonts finish later, a naïve continuation either drops the final frame or writes after the history decision.
5. Only Layer resize currently has explicit page/view/scope/state/zoom cancellation and an Escape special case. Ordinary selection Escape clears selection without restoring the drag baseline. There is no `lostpointercapture` handler; the application handles pointer move/up/cancel by bubbling. Async completion requires an explicit capture-loss policy.
6. Current `pointerCancel` restores the drag document unconditionally. Reusing it after another document mutation can erase that mutation. The Layer context already treats a changed document ID differently by invalidating the drag without restoring its old document; the selection gesture needs the same distinction plus ownership of any published preview.
7. Pointer delta currently divides by the live zoom and samples live snap (8 canvas units). A zoom change while waiting would reinterpret the same physical motion. Bind zoom and snap policy to the gesture, or cancel on change. Do not silently mix start-zoom with current-zoom frames.

## Proposed lifecycle, pending the numerical API

Maintain a dedicated selection gesture with a monotonic epoch, pointer identity, `preparing | active | finishing` phase, immutable starting document/effective tree, explicit context, original client position, latest requested delta/modifiers and revision, last successfully published document, and previous saved state. Context includes document/page/view, Layer or panel scope and state, selected IDs, zoom, snap policy, editing/tool/preview mode, and Affect-all-views policy. Set the intended selection before capturing the context; otherwise its own selection render can invalidate a newly started gesture.

- **Start:** check the property FIFO and structural/admission gates before any serial or selection mutation. Determine the eligible selected participants once. Preserve the existing locked/unplaced skip policy explicitly rather than accidentally measuring or rejecting an inactive participant. Layer plus ordinary-widget resize remains rejected unless a future complete mixed controller is proved.
- **Preparation:** detach the source declaration and explicit adaptive text projection before awaiting fonts. Font preparation may be shared for the gesture because text/style commands are blocked while it owns the document. The native lifetime of the panel rectangle remains unresolved here: do not assume either the first panel or the previous frame's panel is correct. Geometry requests still derive from the original gesture geometry.
- **Move:** record the newest request in canvas coordinates using the bound zoom/snap policy. Coalesce superseded requests instead of treating every pointer event as a FIFO document command. After readiness, plan all participating selection and admitted ordinary widgets into one candidate. Publish only the newest complete valid candidate; never commit one target while another is awaiting measurement or failing.
- **Publish:** a preview may update the displayed document without adding history. Record the exact preview document identity. Before every publication, verify epoch/context and that `docRef` is still either the starting document or this gesture's last publication. Do not accept arbitrary equality of final context after a view round trip; cancellation is monotonic.
- **Pointer up:** record/flush the final request and mark finishing. Keep the session alive while fonts or its last plan are pending. Once that revision is accepted, finalize exactly one undo entry containing the original document, clear redo once, and end the session. Do not call the normal `commit(result)` after previewing: it would capture the preview as the undo baseline. A return to the exact original document creates no history entry.
- **Cancel/failure:** invalidate the epoch immediately, clear pending work and capture ownership, and restore the original document/saved state only while the gesture still owns `docRef`. A newly opened/replaced document must survive. Choose the atomic failure policy explicitly; recommended for this bounded host is cancel the complete gesture and restore baseline, with no undo item. A late font resolution cannot publish or finalize history.

Normal pointer-up causes implicit capture loss. Its subsequent lost-capture notification must not cancel an intentional finishing phase. Unexpected capture loss while actively dragging should cancel. Escape, pointercancel, context change, Undo/Redo, and explicit Cancel must also reach a finishing session, even after `drag.current` would otherwise have been cleared.

## Mutation and history guards

Blocking only `patchSelected` is insufficient. Review `commit`, undo/redo, Delete, paste/duplicate/group, page/collection/view edits, Open/New, rich/point entry, preview/gallery, and keyboard routes. Property/layout controls should reject while a selection gesture is preparing or finishing. Structural/navigation commands must either be disabled or cancel first and then compute their candidate from the restored `docRef`.

Cancellation inside the final `commit(next)` is too late if `next` was already calculated from the preview. This distinction prevents cancelled geometry from leaking into an unrelated edit. A central active-gesture predicate can guard both button handlers and shortcuts, but it must run before candidate construction.

The existing autosave writes displayed documents after 500ms. Async previews can therefore enter autosave before pointer-up unless the host adds a persistence guard or separates preview from committed storage. This is an explicit product-policy decision, not a native inference. Save/export during preparing/finishing should not silently serialize an unintended intermediate frame; blocking them or awaiting accepted finalization is preferable.

## Geometry and adaptive contract still required from the source adapter

- The selection-specific requested size, fit-flag changes, Size/Location ordering, actual-size anchoring for west/north handles, modifier semantics, and allViews argument must come from the pointer controller evidence. Inspector's `{kind:'size', allViews}` alone does not establish pointer behavior.
- A source Size transaction can change the requested dimensions and Location. Reapplying generic `anchorRotatedResize` to its result could overwrite source placement. The numerical adapter should return ordered effects or a complete atomic plan, not just a requested width/height.
- `applySelectionAuthorEffects` is reusable for successful ordered effects: it preserves full Size/Location pairs, shared fit/AlignRight flags, inactive-map cleanup only for actual allViews writes, and derived Layer bounds. Do not diff the final rectangle through the generic author helper and discard these distinctions.
- The current admitted measurement domain is unrotated page/Layer coordinates, explicit selection layout metadata, and no selected-state font override. Existing container/rotation/long-line gaps must remain explicit. No general transform or arbitrary mixed compound resizing is implied.

## Planned browser cases (not yet authored or run)

After the parent/core agree the API: eight handles and untouched axes; measured actual Size/Location versus pointer request; multiple pending moves using only the latest final request; pointer-up before fonts; Escape before readiness and after a preview; pointercancel/unexpected capture loss; view round trip and zoom/snap policy; pending property start rejected without losing that property; one Undo/Redo and no-op return; supported mixed selection atomic failure; unsupported compound/rotation rejection; current/allViews/inactive declaration effects according to the final source contract. Fixtures and outputs will use new selection-pointer paths only.

This report does not claim these behaviors are implemented or validated in a browser. It identifies the host work needed before safely connecting the already bounded selection layout transaction.
