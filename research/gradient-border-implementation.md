# 渐变边框与 RP 11 角度字段

本阶段继续 Axure RP 11 完整重建目标，补齐渐变边框的文档、作者编辑、运行和原生恢复路径。完整原版界面、运行行为、文件互通及协作服务仍未达到等价。

## 独立的填充与边框

`WidgetStyle.strokeGradient` 与已有 `fillGradient` 使用同样的线性起终点、径向中心/双轴、有序色标结构，但分别保存、覆盖及恢复。显式 `stroke` 纯色命令清除边框渐变，显式 `fill` 只清除填充渐变。两者同时有渐变时可以分别编辑，不共享运行时 SVG 定义或临时绘制状态。

边框宽度、四边宽度、圆角、文字样式和不透明度变化保留渐变。自适应视图将“切回相同后备颜色的纯色边框”保存成明确覆盖，取消覆盖才恢复继承。旧工程不补写新字段。输入继续采用完整渐变校验，不接收任意 CSS、URL 或代码。

作者界面复用现有渐变编辑器，通过 Border type 选择 Solid、Linear gradient 或 Radial gradient。Apply 提交完整渐变，Cancel 放弃草稿。基础样式、Selected、交互效果及 Set style 动作均使用同一边界；合法纯色立即预览，非法颜色只保留为输入草稿。具体控件布局及提交手势是独立实现，尚未完成原版作者界面对照。

## 绘制证据与实现

保留的原版 `style.js` 将 `borderFill` 传给与填充相同的线性/径向几何函数，使用独立的 `stroke` 定义和 `.temp_stroke` 状态。初始 SVG 定义的色标位置重用行为也应按填充、边框分别维护。原函数实验与本产品浏览器验证分开记录，不能将受控函数接收端的结果当作原版 GUI 像素。

矢量和线条绘制实际渐变描边。普通表面以连续边框图形绘制渐变，保留原有边框对布局及命中区域的作用。真实浏览器在预览与断网离线页分别比较同色渐变边框和 CSS 纯色边框的实色/空白像素，覆盖非对称四边宽度、极端圆角和椭圆；发现的内孔越过 padding 矩形问题已通过裁切内孔修复。另以像素断言验证填充与边框叠加、透明色标、图片 alpha、继承 currentColor、线条硬色标及调整尺寸。阴影与两种渐变分别绘制。

图片边框遵循已取证的原版特殊规则：线性渐变使用首个色标并保留其透明度，径向使用透明色。`color=0` 拆解为 ARGB 后 alpha 为零，不能解释成可见黑边。完整渐变数据仍保存。内联框架与热区的渐变绘制范围没有被本阶段隐式扩大。

完整原生边框生成类型、箭头、端帽、图案和原版逐像素一致性仍需后续核对。当前官方参考文档确认线条及二维元件轮廓支持线性/径向渐变：[Styling widgets](https://docs.axure.com/axure-rp/reference/styling-widgets/)。该文档用于能力范围，具体算法依据 SHA 固定的 11.0.0.4150 分发文件。19 项受控原函数探针、产品像素用例及源码哈希见 [运行证据](gradient-border-runtime-evidence.md) 与 [清单](gradient-border-runtime-evidence.json)；作者流程见 [作者证据](gradient-border-authoring-evidence.md)。

## 纠正原生角度解释

进一步追踪读取器、写入器和版本分支后确认：现代文件读取渐变端点时，内部旧式角度设为 `NaN`；原生写入器保存的 `fill-angle:0` 是兼容占位。仅旧版本迁移路径读取并转换该角度。因此上一阶段关于“角度转换后归零”及“RP 11 非零角度必需旋转”的推断不成立。

本阶段对已确认的 RP 11 容器按保存端点恢复，有限的非零占位角不会再次旋转点。保留原有容器版本接受范围，缺少明确版本或旧式非零角度仍按未证实范围处理。完整证据、222 项矩形几何、24 项归一化及 4 项版本分支受控 CIL 回放见 [角度报告](gradient-angle-evidence.md)；它们没有执行原版 DLL 或 GUI。

原生填充属性 7 与边框属性 8 已追溯到相同的 Fill 类型及生成器。边框恢复仍遵循原有确定/覆盖标志和完整状态来源要求。现有 11 份真实样本含 9 个已恢复填充渐变、0 个边框渐变；边框格式覆盖使用明确标注的合成样本，不能当成新增真实元件。内存中将 Starter 的 8 个线性渐变占位角改为 73 后，完整导入文档仍严格相等，原文件字节不变；见 [样本审计](gradient-angle-import-audit.json) 与 [哈希清单](gradient-angle-manifest.json)。

## 验证与交付

完整回归通过：2,277 项单测（101 个文件）、449 项原生解析检查、202 项生产构建浏览器流程，以及同一 Windows 程序包上的 23 个桌面检查脚本。浏览器结果零失败、零跳过、零重试恢复；单测使用 maxWorkers=2，原生 Node 检查使用 test-concurrency=2。

桌面新流程实际操作 Border 编辑、完整保存回读与撤销，再分别运行预览、离线导出及嵌套框架；原生文件选择对话框的返回值由测试提供。无脚本错误和网络访问，工程源文件及测试中的设计数据保持不变。编辑器、预览和离线截图已人工查看。其余 22 个桌面脚本覆盖既有原生导入、填充渐变、阴影、框架、树、菜单、表格、矢量、表单和文字/链接功能。

最终源码/证据哈希及 Windows 包字节身份见 [验证记录](gradient-border-verification.json)。[Windows 便携包](../release/REA-Prototype-Studio-0.1.0-win64.zip) 解压后运行整个目录中的 EXE；[演示工程](../artifacts/gradient-border-demo.rea.json) 可继续编辑，[离线演示](../artifacts/gradient-border-demo.html) 可直接打开。本阶段完成渐变边框增量，未宣称完整 Axure 等价，也未将产品 CSS 参考像素检查当作原版 GUI 对照。
