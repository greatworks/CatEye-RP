# 点编辑提交后的外框与自适应视图

本阶段补齐普通点编辑的外框提交行为。修改节点或曲线控制柄后，编辑器按实际曲线的极值重算外框，再将路径归一化；旋转、未移动节点的画布位置和自动适应文本标记保持一致。编辑后仍选中同一节点，可以继续拖动或使用 `1` 尖角、`2` 曲线。数值节点编辑、画布拖动、撤销重做、保存及预览使用同一提交命令。

## 原始证据与入口修正

普通点模式的实际调用链为 `hInw → FjI4 → Cj34 → Kj3n(true) → TN46(points,false)`。`TN46` 在最小尺寸扩张之后归一化，并只向当前有效视图写入变化的位置及尺寸。位置 X/Y、尺寸 W/H 分别成对写入，各轴变化小于 `1e-5` 不产生新声明。共享路径仍是共享内容，AutoFit 标记与其他视图声明保留；Affect All Views 不改变这条专用入口。

早期曾把另一条 `RN4I` 路径当作普通点提交。继续追踪调用者后发现，它属于整形状 Round/Sharp、Break Apart 等不同操作，具有清除 AutoFit、跨视图调整以及不同归一化顺序。该假设在产品集成前已被推翻；初始测试和调查文件保留为纠错记录，不能计为普通点编辑的正确性证据。上阶段关于“可能关闭 AutoFit”的未验证边界由本阶段的调用链证据明确修正，旧报告保持原字节。

- [几何与按键证据](native-point-commit-evidence.md)：98 个有界案例、21 个保留 CIL 方法回放。包含实际 Bézier 极值、非对称向外取整、最小尺寸、旋转、提交分派与 D1/D2 映射。
- [视图写入证据](native-point-commit-format-evidence.md)：79 个通过案例，区分 TN46 当前视图写入和 RN4I 的跨视图策略。
- [独立复核](native-point-commit-final-review.md)：135/135，通过完整文档期望核对 Base、命名视图、共享视图及嵌套容器，源码在审核期间保持不变。
- [数值输入修复复核](native-point-commit-inspector-review.md)：33/33 有界检查，通过同值/变值归一化、非法输入及与旧默认行为的成对比较；未替代实际 React/浏览器验证。

只执行了有界的指令回放及独立重建代码，没有执行原版 DLL 方法。完整轮廓组装和 `hN4K` 编排尚非端到端执行证据。原版编辑器的截图采集仍返回 `FrameArrived timed out`，没有新增原版画布交互或像素对照结论。

## 实现范围

五个生产文件发生变化：

- `src/model/vector-commit.ts`：纯几何计算。曲线外框使用导数根和端点，不使用控制柄包围盒。实现保留证据中的系数/判别式阈值、单侧近整数例外、`max(strokeWidth,1)` 最小轴、绕旧/新中心的旋转与归一化。
- `src/model/adaptive.ts`：通过专用点编辑命令一次提交共享路径及当前视图几何；保留 AutoFit、内容、样式、未启用视图及其他声明。无实际变化直接返回原页面，非法输入在文档写入前拒绝。
- `src/App.tsx`：将节点编辑会话身份与变化的几何外框分开，自己的提交不会使覆盖层重挂载而丢失节点选择。
- `src/components/CanvasVectorTools.tsx`：手势快照记录外框；外部外框/路径变化取消未完成拖动，完成手势只提交一次。按键改为原版元数据对应的 `1` 尖角、`2` 曲线。
- `src/components/Inspector.tsx`：节点及控制柄数值提交后重置本地输入草稿，确保归一化结果即使与原值相同也能显示；其他数值控件保持既有默认行为。

原有渲染器、运行时和原生文件读取器未改动；没有新增依赖。README 与 Windows 使用说明同步更新。仅切换填充规则沿用既有共享内容命令，不重算外框，是明确的兼容性选择。进入、取消、零位移不产生文档历史，以及数值编辑入口，也是本应用的事务策略，不能称作已观察到的原版 GUI 行为。

## 回归与纠错记录

- 普通提交正确入口的单元红测保存在 `native-point-commit-tn46-unit-red.json`。额外的极小系数回归曾失败：两个导数系数都很小时，原版仍计算二次判别式；误丢根会使最小外框 Y 从 -2 变成 -1。修正分支后，新增 38 项单测通过。
- 全量单元测试 3571/3571，149 个文件；原生文件读取测试 698/698；TypeScript 通过。最终证据文件冻结后，38 项新单测另行重跑并核对输入前后哈希，消除研究文件完成时间与全量运行重叠的不确定性。
- 修正入口后的旧版本浏览器回归为 44 通过、9 失败；原始更早的 RN4I 假设测试另外保留。新版本首次重点回归 51/53，10 项新增测试全通过。剩余两项旧测试把归一化坐标当作固定画布坐标；外框变化后这种断言不再成立。
- 两项旧测试改为按各自外框计算节点/控制柄的画布坐标，并独立断言曲线外框 `(100,89,221,111)`；所有无关文档字段、历史及重新打开的精确检查仍保留。随后重点浏览器回归 53/53，零重试、零跳过。
- 全量浏览器首次为 294 通过、1 失败；最后一项仍把连续数值编辑的相对坐标当作固定值。修正后的测试逐次核对输入相对当前外框的画布坐标，并逐坐标验证其他节点/控制柄不动、无关文档数据不变；完成节点编辑后另行核对普通移动与缩放保留归一化路径。该文件四项定向复测全部通过，生产代码及已测试构建没有变化。295 个唯一案例的覆盖清单保留原始 294/1 结果及后续 4/4 结果，没有将其伪装成一次全量零失败运行。
- 随后的桌面截图复核发现真实界面缺陷：输入 -25% 后，路径正确保存为归一化 0%，但属性栏仍显示 -25%。新增浏览器断言先在旧构建失败，再用 NumberField 的局部 opt-in 修复。修复后 3571 项单测和 14 项重点浏览器测试通过，并重新构建、打包和执行全量验证。首次包、截图及日志保存在 `.build/native-point-commit-before-field-fix`，不能当作最终包。
- 最终修复构建的完整浏览器运行 **295/295，零失败、零跳过、零重试**；权威报告为 `.build/native-point-commit-release-final-e2e.json`。这是重新执行的全套结果，与此前合并覆盖清单分开保存。
- 最终同一 ASAR 的 **8 项桌面脚本全部通过**。本阶段核心流程包括 6 次原生保存、Undo/Redo、从不同状态重新打开、预览及断网导出；未出现控制台错误或联网请求。三张新截图均已人工复核，属性栏显示归一化后的 0%，画布、预览和离线页面的形状及文字完整可见。截图只证明本应用的显示结果，不证明与原版逐像素一致。
- 发布校验首次因早期模型审核绑定了修复前的 Inspector 哈希而停止。冻结的旧审核未修改；验证器只对这份清单中的这一个确切旧哈希核验阶段备份，并在最终清单记录对应关系。当前 Inspector 由单独的 33 项审核、最终构建、单测及浏览器/桌面结果绑定。
- 首次旧矢量桌面检查还暴露测试期望不足：Electron 输入点因小数表面原点产生约 `3e-5` 像素偏差，已超出原版取整阈值；拖动首节点也会移动它的出控制柄。测试现在根据实际输入端点独立计算向外取整，并检查应移动的首节点/出柄与其余所有画布坐标。产品几何没有为此更改。
- 全量浏览器、同一 ASAR 的桌面回归、截图人工复核、发布 ZIP 与文件哈希以 [最终验证清单](native-point-commit-verification.json) 为准。各次日志和失败输出独立保留；旧报告、样例及上版安装包保留在阶段备份中。

## 使用与边界

打开 [示例工程](../artifacts/native-point-commit-demo.rea.json)，选择形状，修改 Node X % 或进入 Edit points 拖动锚点。外框跟随已提交的曲线变化，Undo/Redo 恢复完整状态；[离线示例](../artifacts/native-point-commit.html) 用于核对保存的几何。

尚未完成：隐藏部分边框或独立四角参数的点编辑、无参与线段的轮廓、原版完整轮廓重排及退化过滤、一般仿射变换、连接器约束、独立 RN4I 整对象命令、完整 RP 写回与团队协作。空线段输入目前原子拒绝；现有有限坐标和尺寸预算继续生效。键位映射有指令证据，上层修饰键策略及原版鼠标/历史行为仍未全面核对。

另一个待核对的数值边界是极小非零旋转：保留的 `hN4K` 在 IL 0x14–0x2b 比较 `uIuQ` 与 `1e-5` 后可能转入无旋转分支；本实现对非零角统一采用中心旋转，当前几何探针未覆盖这条分派阈值。不能据现有 0°/30°/37°/90°/180° 案例推断该边界完全一致。

这是独立编辑器的一项已界定实现，不代表“一模一样的 Axure RP 11”目标已完成。
